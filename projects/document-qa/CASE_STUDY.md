# Case Study: Document QA

## Resumen

Proyecto demostrativo para revisar expedientes digitales con enfoque de QA documental. Convierte una tarea administrativa en un sistema de control de calidad: campos, evidencia, estado, errores frecuentes y observaciones.

## Problema

Los expedientes pueden fallar por datos incompletos, documentos faltantes, nombres inconsistentes o criterios de revision poco claros.

## Objetivo

Crear una metodologia reusable para revisar documentos antes de enviarlos o capturarlos.

## Checklist base

| Area | Revision | Estado |
|---|---|---|
| Identificacion | nombre visible y documento vigente | pendiente |
| Solicitud | datos obligatorios completos | pendiente |
| Comprobante | direccion legible y consistente | pendiente |
| Documento base | datos principales visibles | pendiente |
| Evidencia | imagen clara y relacionada | pendiente |
| Observaciones | inconsistencias registradas | pendiente |

## Flujo de revision

1. Confirmar que todos los archivos existen.
2. Revisar legibilidad.
3. Comparar datos repetidos.
4. Marcar inconsistencias.
5. Redactar observacion breve.
6. Asignar estado final.

## Errores frecuentes

- Nombre escrito de forma distinta.
- Direccion incompleta.
- Documento ilegible.
- Archivo equivocado.
- Falta de firma.
- Fechas contradictorias.

## Entregable final

Un reporte con documentos revisados, errores encontrados, prioridad, accion requerida y observacion lista para copiar.

## Servicio relacionado

Asistente virtual tecnico, control documental, data entry, revision de requisitos y QA administrativo.

## Mejoras futuras

- Tabla de validacion.
- Semaforo de estado.
- Plantillas por tipo de revision.
